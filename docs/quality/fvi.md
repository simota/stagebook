# 機能価値の評価（FVI）

機能の拡充を、同じ基準で前後比較するための記録。基準は着手前のコミット `a43c84c` の時点で確定し、以後は変えない。利用データやユーザーの要望は手元にないので、主要タスクは「ライブハウスに出るバンドが、公演ごとにセットリスト・ステージ図・音響照明シートを用意する」という前提から立てた仮説である。

## 主要タスク（固定）

| # | タスク | 完了条件 |
|---|---|---|
| T1 | 曲を追加して演者用セットリストを印刷する | 印刷プレビューに反映される |
| T2 | スタッフ用セットリストを作る | 曲ごとの尺に加え、開始時刻が載っている |
| T3 | ステージ図とチャンネル表を作る | パーツの配置と CH 番号が帳票に載る |
| T4 | 曲ごとの照明・音響の指示を作る | 音響照明シートに載る |
| T5 | まとめてテキストで入力する | テキストからセットリストが作られる |
| T6 | 過去の公演で演奏した曲を、今回のセットリストに使う | BPM・キー・尺・照明などの指示ごと、再入力なしで入る |
| T7 | 公演の内容をメンバーや会場スタッフに渡す | 相手が同じ内容を開いて印刷できる |

| T10 | メモ帳などにある曲名だけの一覧を取り込む | 番号を振り直さずに貼り付けて取り込める |

## 指標と判定条件

- **UVI（ユーザー価値）** = Σ（対応状況）÷ 10 × 100。対応状況は、完全に対応 = 1 / 回り道すればできる = 0.5 / できない = 0
- **CEI（能力の広さ）** = 完全に対応しているタスクの数 ÷ 10 × 100
- **UEI（操作の効率）** = 各タスクの点数の平均。点数はアプリ内で最短の操作手数で決める: 3手以下 = 100 / 6手以下 = 75 / 10手以下 = 50 / 11手以上か、アプリの外での計算などが必要 = 25 / できない = 0
- **FCI（完成度）** = 各機能が満たしているチェック項目の割合。チェック項目は5つ: 画面とつながっている / 保存される / 異常な入力や境界を扱う / ユニットテストがある / e2e テストがある
- **FRI（信頼性）** = 0.5 × テストの成功率 + 0.5 ×（異常な入力の経路がテストされている機能の割合）
- **FVI** = 0.25 UVI + 0.25 FCI + 0.20 CEI + 0.15 UEI + 0.15 FRI

既存の機能と新しい機能は分けて評価する。新しい機能の改善前は「未提供」とし、0点にはしない。手数は人が数えたもの（E1）、テストの結果は実行結果（E2）。
