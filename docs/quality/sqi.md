# 品質評価（SQI）

設計・アーキテクチャ・デザイン・UI/UX を、同じ基準で改善前後に採点するための記録。基準（評価項目・重み・判定条件・測定方法）は、改善に着手する前のコミット `a155d88` の時点で確定し、以後は変更しない。

SQI は独自の採点基準による評価で、物理量のような客観値ではない。実ユーザーでのテストは行っていない。AI がブラウザを自動操作した結果は「自動テスト」であって、ユーザーテストではない。

## 測定方法と条件

| 種別 | 方法 | 再現手順 |
|---|---|---|
| 静的 | import の依存グラフ（循環・層の向き）、`src/app.css` で `:root` の外に直接書かれた色の数、ビルド後の gzip サイズ | `npm run build && node scripts/static-metrics.mjs` |
| 動的 | Playwright + システムの Chrome。axe-core による自動のアクセシビリティ検査、390px 幅での横はみ出し、入力の遅延、キーボード操作の可否、壊れた保存データでの起動 | `npx playwright test e2e/measure.spec.ts` → `test-results/metrics.json` |
| 機能の非劣化 | 主要な操作の流れ（6本）と印刷のテスト（1本）。改善前のコードでも通ることを確認済み | `npm run e2e` |

固定した条件: Chrome（Playwright の `channel: chrome`）、ビューポートは 1600×1000（デスクトップ）と 390×844（スマホ）、テーマはライト（ダークは別に計測）、言語は日本語、データは毎回まっさらな状態から読み込むサンプル公演、権限なし（ログインのない静的アプリ）。

主要なタスク（開始は「サンプル公演が開いた状態」）

1. 曲を追加し、演者用セットリストに反映させる（完了 = プレビューに表示され、再読み込み後も残る）
2. ステージ図のパーツを動かし、不要なパーツを消す（完了 = 位置が保存され、紐づくチャンネルも消える）
3. JSON を書き出して読み込む（完了 = 公演が1件増える）
4. テキストで書いて反映する（完了 = プレビューに反映され、誤りがあれば行番号付きで知らせる）
5. 印刷する（完了 = A4 縦2枚・横2枚）

## 採点のしかた

各項目は 0〜5 点で、次の共通基準に沿って採点する: 0 = 要件をほぼ満たさない / 1 = 重大な欠陥が複数ある / 2 = 基本はあるが問題を繰り返している / 3 = 実用上おおむね問題ない / 4 = 一貫して高い品質 / 5 = 例外的なケースまで根拠付きで確認済み。

領域スコア = Σ（重み × 評点 ÷ 5）。SQI は4領域を同じ重み（0.25 ずつ）で平均する。

根拠の強さ: E1 = コードや画面を見て判断 / E2 = 再現できる静的解析・自動テスト / E3 = 実測（ただし合成環境での実測）。根拠のない項目は採点せず「未検証」とする。

### 項目ごとの判定条件

**DQI（設計）**

| 項目 | 重み | 判定条件 |
|---|---:|---|
| 責務分離 | 20 | 変更理由の違う処理が同じモジュールに混ざっている箇所が 0 件なら 5 / 軽微なものが1件なら 4 / 軽微なものが2〜3件なら 3 / 重大なもの（表示とドメインの混在など）が1件以上なら 2 |
| 凝集度 | 15 | 目的外の公開物を持つモジュールが 0 件なら 5 / 1件なら 4 / 2件なら 3 / 3件以上なら 2 |
| 契約の明確性 | 15 | 外から入るデータ（読み込み・保存領域）を全部検証し、テストもあれば 5 / 全部検証しているが一部テストがなければ 4 / 検証していない入口が1つあれば 3 / 2つ以上なら 2 |
| 変更容易性 | 15 | 代表的な変更（項目の種類を足す、照明の色を足す）で、同じ語彙を二重に定義している箇所が 0 件なら 4（5 にはテストで担保されていることも必要）/ 1件なら 3 / 2件以上なら 2 |
| 可読性 | 10 | 命名と構造が一貫し、説明が必要な分岐がなければ 4 / 読みにくい箇所が散在すれば 3 |
| テスト容易性 | 15 | ドメイン・保存・画面のそれぞれに自動テストがあれば 5 / 2層にあれば 4 / ドメインだけなら 3 / テストがなければ 1 |
| 不変条件と例外 | 10 | 想定できる失敗（壊れたデータ、保存の失敗）がすべてユーザーに伝わり、アプリが落ちなければ 5 / 落ちないが一部伝わらなければ 4 / 失敗の経路が1つ未処理なら 3 / 2つ以上未処理なら 2 / 起動できなくなる経路があれば上限 2 |

| 余白と情報の密度 | 10 | 狭い幅でも詰まりすぎた表がなければ 4 / 狭い幅で使いにくい密度の表が1つあれば 3 |

### e2e で再現した欠陥

| 欠陥 | 再現条件 | 修正 |
|---|---|---|
| ステージのパーツを選んだまま、チャンネル表の並べ替えハンドルなどで矢印キーを押すと、パーツも動く | パーツを選ぶ → 別の操作部品にフォーカス → 矢印 | キー操作を、図の上（かフォーカスなし）にあるときだけ受ける |
